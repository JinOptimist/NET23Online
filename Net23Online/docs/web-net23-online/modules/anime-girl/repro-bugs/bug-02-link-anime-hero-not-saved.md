# Сценарий: связь аниме и героини иногда не сохраняется

## Что заметил тестировщик

На главной странице модуля Anime Girl форма «привязать аниме к героине» отрабатывает без ошибок (редирект на Index), но подпись с привязанными тайтлами у героини не меняется.

## Предварительные условия

- В базе есть минимум **два** разных аниме (A и B).
- Есть героиня, которая **уже** привязана к аниме A (через ту же форму или при создании).
- Приложение запущено, страница `/AnimeGirl/Index` открывается.

## Шаги воспроизведения

1. Открыть `/AnimeGirl/Index`.
2. В секции привязки аниме и героини выбрать в первом списке аниме **A**, во втором — героиню, которая **ещё ни к чему не привязана**.
3. Нажать кнопку привязки. Убедиться, что у героини в списке появилось имя аниме A.
4. Не перезагружая приложение, снова открыть `/AnimeGirl/Index`.
5. В той же форме выбрать аниме **B** и **ту же героиню**.
6. Запомнить числовые **Id** выбранного аниме и героини (из выпадающих списков или из таблицы `/AnimeGirl/TableData`).
7. Нажать кнопку привязки.
8. После редиректа проверить подпись героини: должна ли там фигурировать аниме B.
9. Повторить шаги 5–8 для **другой пары** аниме/героини с другими Id, убедившись, что у второй героини изначально тоже есть одна привязка.

## Ожидаемое поведение (со слов аналитика)

Героиня может быть связана с несколькими аниме; после шага 7 в подписи должно появиться аниме B (или оба тайтла).

## Фактическое поведение

Иногда после шага 7 страница обновляется «успешно», но состав привязанных аниме **не меняется**. Для других пар Id всё срабатывает с первого раза.

## Подсказки для расследования (могут вводить в заблуждение)

- Проверьте, не блокирует ли повторную привязку **уникальный индекс в БД** — в логах SQL может мелькать `DbUpdateException`, которую MVC глотает.
- Убедитесь, что форма на Index отправляет **POST**, а не теряет поля `animeId` / `heroId` из‑за автозаполнения браузера.
- Посмотрите **SignalR** `NewAnimeCreated` — возможно, клиентский скрипт перерисовывает каталог и затирает связи.
- Сравните с прямым вызовом API — может, MVC-экшен и репозиторий расходятся в логике.
- Проверьте кэш EF: `DbContext` мог остаться с устаревшим графом `Animes` / `Heroes`.

## Что зафиксировать в отчёте

- `animeId` и `heroId` для успешного и неуспешного случая.
- Список аниме у героини **до** и **после** шага 7.
- Сумма `animeId + heroId` для обоих случаев (тестировщик просил — «вдруг закономерность»).
