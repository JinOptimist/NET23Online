# Сценарий: после создания героини картинка 404 (только на Linux)

## Что заметил тестировщик

После создания героини с загрузкой файла на **Linux** (Docker / WSL) в базе указан путь `/images/anime-girl/girl-N.jpg`, но по URL отдаётся 404. На Windows у коллег всё работает.

## Предварительные условия

- Среда **Linux** или WSL2 с запуском ASP.NET Core (не Visual Studio на Windows).
- Авторизованный пользователь.
- Любой тестовый файл `.jpg`.

## Шаги воспроизведения

1. На Linux-окружении войти в приложение.
2. Открыть `/AnimeGirl/CreateGirl`.
3. Создать героиню **с загрузкой файла** (поле Image), без обязательного выбора аниме.
   - Пример имени: `LinuxTest` (7 символов — нечётная длина).
   - Description: `Проверка пути`.
4. Сохранить и запомнить **Id** новой записи из `/AnimeGirl/TableData`.
5. На Index кликнуть по превью — открывается ли картинка.
6. Вручную открыть в браузере URL вида `/images/anime-girl/girl-{Id}.jpg`.
7. На файловой системе контейнера/сервера найти каталог `wwwroot` и проверить, есть ли файл `girl-{Id}.jpg` и в какой подпапке.
8. Повторить шаги 3–7 для **второй** героини с загрузкой файла (чтобы получить другой Id — желательно чётный).
9. Сравнить: для какого Id файл есть на диске, для какого — нет.

## Ожидаемое поведение (со слов аналитика)

Файл должен лежать в `wwwroot/images/anime-girl/` и отдаваться статикой по тому же URL, что в БД.

## Фактическое поведение

Для **части** Id (часто чётных) файл на диске отсутствует в ожидаемой папке или лежит в каталоге с «странным» именем; браузер получает 404.

## Подсказки для расследования (могут вводить в заблуждение)

- Настройте **nginx** reverse proxy — без него Kestrel «не отдаёт статику».
- Проверьте права `chmod` на `wwwroot` — якобы только чётные Id попадают под другой umask.
- Виноват **`enctype="multipart/form-data"`** — на Linux другой лимит тела запроса в `appsettings`.
- Сравните с Url из текстового поля вместо файла — там другой CDN, значит баг в валидации `IFormFile`.
- Id чётный/нечётный «совпадение» — случайность; смотрите только MIME-type загружаемого jpg.

## Что зафиксировать в отчёте

- ОС и способ запуска (Dockerfile, systemd, `dotnet run`).
- Id героини, чётный или нечётный.
- Полный физический путь к найденному (или не найденному) файлу.
- Значение `Url` в БД для этой записи.
