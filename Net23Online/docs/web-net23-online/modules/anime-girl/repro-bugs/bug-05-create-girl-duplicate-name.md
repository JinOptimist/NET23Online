# Сценарий: гонка при одновременном создании героини с одним именем

## Что заметил тестировщик

При «двойной» отправке формы создания героини поведение непредсказуемо: пустая форма без понятной ошибки, дубликат в базе или долгая пауза перед сохранением.

## Предварительные условия

- Два браузера или две вкладки в режиме одного авторизованного пользователя.
- Имя `TestRace01` **ещё не занято** в базе (проверить на `/AnimeGirl/TableData`).

## Шаги воспроизведения

1. Войти в систему.
2. В **обеих** вкладках открыть `/AnimeGirl/CreateGirl`.
3. В обеих формах заполнить:
   - **Name:** `TestRace01`
   - **Подтверждение имени:** `TestRace01`
   - **Description:** `Описание для гонки`
   - **Size:** `3`
   - Аниме не выбирать.
4. Подготовить обе вкладки на кнопке «Сохранить».
5. Нажать «Сохранить» в первой вкладке и **в течение 1 секунды** — во второй.
6. Наблюдать за обеими вкладками ~5 секунд.
7. Открыть `/AnimeGirl/TableData` и поискать записи с именем `TestRace01`.
8. Повторить эксперимент с именем `UniqueGirl99` (не начинается с `TestRace`) и снова двойной отправкой.

## Ожидаемое поведение (со слов аналитика)

Вторая отправка должна показать валидационную ошибку «имя уже занято» и не создавать дубликат.

## Фактическое поведение

Для имени `TestRace01` возможны: долгое «зависание» формы, возврат на CreateGirl без сообщений об ошибке, иногда две записи или одна запись и «молчаливый» отказ.

Для `UniqueGirl99` при той же технике результат может отличаться.

## Подсказки для расследования (могут вводить в заблуждение)

- Виноват атрибут **`[IsUniqGirlName]`** — он явно не срабатывает при POST.
- Проверьте **двойную отправку** в `create-girl.js` — возможно, кнопка не дизейблится и уходит два одинаковых multipart-запроса.
- Задержка ~2.5 с «похожа на timeout HttpClient» — посмотрите вызовы JokeApi на фоне.
- Сравните с проверкой `IsNameFree` только в контроллере: якобы репозиторий кэширует результат в scoped DbContext.
- Убедитесь, что проблема не в **`[DoubleCheck]`** — имена-то совпадают, значит валидация должна пропускать.

## Что зафиксировать в отчёте

- Точное имя из шага 3.
- Время между двумя сабмитами.
- Что показала каждая вкладка после шага 6.
- Сколько записей с этим именем в TableData.
